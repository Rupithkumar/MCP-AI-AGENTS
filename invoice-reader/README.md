# Invoice Reader: scan to structured data, with self-checks and a review queue

Reads an invoice image and returns vendor, invoice number, date, currency, subtotal, tax and total as clean data. The
point of the project is not just extraction but **knowing when it is wrong**: the totals must add up (and the line items
must add up to the subtotal), and a document that fails the check goes to a human review queue instead of being trusted.

```
image -> OCR (Tesseract) -> extractor -> self-check -> repair or LLM fallback -> accepted / flagged for review
```

| System | What it does |
|---|---|
| `rules` | Regular expressions on the OCR text. Free and instant. |
| `rules_repair` | Rules plus an arithmetic repair: if subtotal + tax != total, rebuild the field that looks like a misread. |
| `llm` | A language model reads the OCR text and returns JSON (any OpenAI-compatible API, e.g. Groq). |
| `cascade` | `rules_repair` first; the LLM is called **only** when the self-check still fails. Fewer calls, same safety net. |

## Results (measured)

150 synthetic invoices on a fresh seed that I did not tune against, scanned at three quality levels. Full tables in `RESULTS.md`.

| System | Docs fully correct | Flagged for review | Silent errors | Accuracy of accepted docs |
|---|---|---|---|---|
| rules | 79.3% | 18.0% | 2.7% | 96.7% |
| rules_repair | 80.7% | 16.7% | 2.7% | 96.8% |
| llm, cascade | **not measured yet** (needs an API key; run the commands below) | | | |

*Silent error* = wrong and not flagged, so nobody looks at it. The self-check caught 86% of wrong documents.

What the numbers say, honestly:
- Repair helped a little (+1.4 points; subtotal errors roughly halved) and did not add silent errors.
- The biggest error source is the **rupee sign**: Tesseract reads it as a digit or not at all, so 22 of 150 documents (all INR) lose the currency. The self-check flags them rather than guessing. A vision-language model that reads the image directly is the real fix, and is the obvious next step.
- A garbled vendor name or invoice number passes the arithmetic check. That is where the remaining silent errors come from.
- During development a generator bug (text clipped at the page edge) made the baseline look 13 points worse than it is. Fixing it is why the final numbers are higher; I mention it because it is a good example of why you inspect your failures.

## Run it (Windows, PowerShell)

```powershell
# 1. environment
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 2. install Tesseract OCR (a separate program): https://github.com/UB-Mannheim/tesseract/wiki
#    Then either add it to PATH, or:  $env:TESSERACT_CMD="C:\Program Files\Tesseract-OCR\tesseract.exe"

# 3. tests (29), including real OCR if Tesseract is found
python -m pytest

# 4. make data and measure the no-API systems (OCR on 150 images takes about a minute and a half, then it is cached)
python -m src.generate --n 150 --seed 777 --out data/invoices_heldout
python -m src.evaluate --folder data/invoices_heldout --results results/heldout --systems rules,rules_repair

# 5. the LLM systems (set your own key; never commit it)
$env:LLM_BASE_URL="https://api.groq.com/openai/v1"; $env:LLM_MODEL="openai/gpt-oss-120b"; $env:LLM_API_KEY="<your key>"
python -m src.evaluate --folder data/invoices_heldout --results results/heldout --systems llm,cascade --limit 60 --delay 2

# 6. report
python -m src.report --results results/heldout
```

Use your own invoices: put images in a folder with a `truth.jsonl` (fields id, image, level, plus the seven answers), or call
`read_text` and `RuleRepairExtractor().extract(text)` directly on a single file.

## Limitations (read before presenting)

- **Synthetic data.** Three layouts, generated by me. Real invoices vary far more, so expect lower scores. Never present these numbers as real-world accuracy.
- **Rule weaknesses are by design.** The rules are a baseline; they were developed while looking at generated data (the quoted results use a separate seed).
- **The LLM and cascade results do not exist yet.** The code and fake-client tests pass, but no real model has been run.
- **Text only.** OCR errors that change a character are invisible to the arithmetic check.

## Layout

```
src/generate.py   synthetic invoices with ground truth and three scan-quality levels
src/ocr.py        Tesseract with simple preprocessing
src/extract.py    rules, rules+repair, LLM, cascade
src/validate.py   self-checks and arithmetic repair
src/evaluate.py   per-field, per-quality, silent-error and review-queue metrics
src/report.py     REPORT.md
tests/            29 tests (parsing, repair, cascade with a fake LLM, generator, real OCR end to end)
```
